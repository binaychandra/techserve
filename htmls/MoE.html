§01 — Core Idea

Not every token needs
every neuron.

A dense transformer layer activates all its parameters for every token. MoE asks: what if we had many specialized sub-networks, and each token only visited the ones most relevant to it? Massive capacity, surgical compute.

🧠

The Expert Analogy

Like a hospital with specialist doctors — a patient (token) sees only the relevant specialist (expert), not every doctor on staff. Each expert becomes deeply specialized through repeated exposure to similar inputs.

🔀

The Router / Gating Network

A lightweight learned function that sees each token's embedding and decides which experts should handle it. Usually a simple linear layer followed by softmax, outputting a probability distribution over all experts.

⚡

Sparse Activation

Only Top-K experts (usually K=1 or K=2) are activated per token. With 64 experts and K=2, only 3.1% of expert parameters fire for any single token — massive parameter counts, fixed compute budget.

🏗️

Where It Lives

MoE replaces the FFN (Feed-Forward Network) sub-layer in a Transformer block. The attention sub-layer remains dense and shared. Each expert is itself a standard FFN (two linear layers + activation).

§03 — Mathematics

The Routing Equations

MoE math is elegant: a learned linear gate, a softmax-with-noise, Top-K selection, and a weighted sum. The devil is in the auxiliary loss that keeps experts from collapsing.

Step 1 — Gating Logits
H(x) = x · W_gate + StandardNormal() · Softplus(x · W_noise)
W_gate (d_model × N_experts) is the learnable routing matrix. The noise term — used in Switch Transformer and GShard — adds randomness during training for better expert exploration. W_noise is also learned. At inference, noise is typically disabled.
Step 2 — Top-K Selection & Gating Weights
TopK(H, K) → keep K largest logits, set rest to -∞

G(x) = Softmax(TopK(H(x), K))
Setting non-selected logits to −∞ before softmax ensures they contribute exactly zero weight. This is how sparsity is enforced — a clean hard gate. The remaining K weights sum to 1.0, creating a convex combination of expert outputs.
Step 3 — Expert Computation & Weighted Sum
y = Σᵢ₌₁ᴷ G(x)ᵢ · FFNᵢ(x)

FFNᵢ(x) = W₂ᵢ · GELU(W₁ᵢ · x)
Each expert i is a full FFN with its own parameters (W₁ᵢ, W₂ᵢ). Only K=1 or K=2 are computed. The outputs are scaled by the gate weights and summed — a learned, input-dependent interpolation between specialist outputs.
Auxiliary Load-Balancing Loss
L_aux = α · N · Σᵢ fᵢ · Pᵢ

fᵢ = fraction of tokens routed to expert i
Pᵢ = mean gating probability assigned to expert i
Without this loss, the router collapses — it keeps sending all tokens to one expert (rich-get-richer). L_aux penalizes uneven distribution. α is a hyperparameter (typically 0.01–0.1). This is the most critical MoE-specific training detail.
§04 — Why MoE

The Case for Sparse Models

MoE isn't a trick — it's a fundamental change in the scaling law regime. More parameters per FLOP, better specialization, practical throughput at massive scale.

01

Decoupled Parameter vs Compute Scaling

You can 10× the parameters without 10× the FLOPs. Mixtral 8×7B has 46.7B total params but only 12.9B active per token — same compute as a 13B dense model with the capacity of a 47B model.

02

Better Quality per FLOP

Empirically, MoE models achieve lower perplexity at the same training FLOPs vs dense models. Switch Transformer matched or exceeded T5-11B quality using far fewer compute operations.

03

Expert Specialization

Experts develop interpretable specializations — some attend to syntax, others to semantics, domain-specific reasoning, or certain languages. This division of labor emerges naturally from training.

04

Faster Training Throughput

With expert parallelism across devices, each device hosts a subset of experts. Tokens are dispatched to the correct device, processed, and returned. This enables linear scaling of training throughput.

05

Lower Inference Latency (per token)

Since only K experts fire per token, latency is determined by active parameters, not total parameters. A 141B MoE model (DeepSeek-V3) can match the latency profile of a 20–30B dense model.

06

Modular & Composable

Experts can be pruned, merged, or swapped post-training. Research shows you can extract language-specific or domain-specific expert subsets and deploy lightweight specialist slices of a large MoE.

Parameter Efficiency — MoE vs Dense at Equal FLOPs

§07 — Training

Training an MoE Model

Training MoE requires careful orchestration of expert parallelism, gradient flow through sparse operations, and auxiliary losses. Here's the full pipeline:

1. Expert Parallelism Setup

Distribute experts across devices. With 64 experts across 8 GPUs, each GPU owns 8 experts. Data parallelism handles batch distribution while expert parallelism handles routing. Combine with tensor and pipeline parallelism for frontier-scale training.

2. All-to-All Dispatch

After gating decisions, tokens must physically travel to the device hosting their chosen expert. This all-to-all communication is the main latency bottleneck. Each token carries its embedding vector across the interconnect.

3. Capacity Factor & Token Dropping

Each expert has a capacity: max_tokens = (batch_size / N_experts) × capacity_factor. If more tokens arrive than capacity, overflow tokens are dropped (passed through with a residual connection). Capacity factor of 1.25–2.0 balances utilization vs waste.

4. Expert Forward Pass + All-to-All Return

Each device computes its experts' outputs for the tokens it received. Then a second all-to-all gathers results back to each token's origin device. Two all-to-all operations per MoE layer per forward pass.

5. Gradient Flow & Auxiliary Loss

Gradients flow through the gating weights G(x) via straight-through estimators or dense gradient approximations. The auxiliary loss L_aux is added to the main language modeling loss with weight α, typically 0.01–0.1. Too high and it kills task performance; too low and experts collapse.

6. Router Z-Loss (PaLM-2 trick)

Penalize large logit magnitudes in the router: L_z = (1/B) · Σ log²(Σⱼ exp(H(x)ⱼ)). Stabilizes training by preventing router logits from exploding, which would make the softmax near-deterministic and hard to optimize.

Key Insight: MoE models need more tokens to converge than equivalent dense models. The router needs to learn meaningful specialization, which takes longer than learning a single FFN. Researchers typically train MoE for 1.5–2× more steps than comparable dense baselines.

moe_router.py — Gating Network 
import torch
import torch.nn as nn
import torch.nn.functional as F
from typing import Tuple

class MoERouter(nn.Module):
    """
    Learned gating network for Mixture of Experts.
    Produces Top-K sparse gate weights for a batch of tokens.
    """
    def __init__(
        self,
        d_model: int,        # Input embedding dimension
        n_experts: int,      # Total number of experts
        top_k: int = 2,      # Experts activated per token
        noise_std: float = 1.0,  # Noisy top-k exploration noise
    ):
        super().__init__()
        self.n_experts = n_experts
        self.top_k = top_k
        self.noise_std = noise_std

        # Core routing linear: maps d_model → n_experts logits
        self.gate = nn.Linear(d_model, n_experts, bias=False)

        # Learned noise scale (Noisy Top-K from Shazeer et al. 2017)
        self.noise_scale = nn.Linear(d_model, n_experts, bias=False)

    def forward(
        self,
        x: torch.Tensor,           # (batch, seq_len, d_model)
        training: bool = True,
    ) -> Tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
        """
        Returns:
            dispatch_weights  (B, S, top_k)  — softmaxed gate scores
            expert_indices    (B, S, top_k)  — which experts are chosen
            router_logits     (B, S, n_experts) — raw logits for aux loss
        """
        B, S, D = x.shape

        # Raw logits
        logits = self.gate(x)  # (B, S, n_experts)

        # Add multiplicative noise during training for exploration
        if training and self.noise_std > 0:
            noise = torch.randn_like(logits)
            noise_scale = F.softplus(self.noise_scale(x))
            logits = logits + noise * noise_scale * self.noise_std

        # Top-K selection: zero out all but top_k logits
        top_k_logits, top_k_indices = torch.topk(
            logits, self.top_k, dim=-1
        )  # both: (B, S, top_k)

        # Softmax ONLY over the top-k slots — sparse gating weights
        dispatch_weights = F.softmax(top_k_logits, dim=-1)

        return dispatch_weights, top_k_indices, logits


def load_balancing_loss(
    router_logits: torch.Tensor,    # (B, S, n_experts) raw logits
    expert_indices: torch.Tensor,   # (B, S, top_k)
    n_experts: int,
    alpha: float = 0.01,
) -> torch.Tensor:
    """
    Auxiliary loss from Switch Transformer.
    Encourages uniform distribution of tokens across experts.
    L = alpha * N * sum(f_i * P_i)
    """
    B, S, n_e = router_logits.shape
    n_tokens = B * S

    # f_i: fraction of tokens assigned to each expert
    flat_indices = expert_indices.reshape(-1, expert_indices.shape[-1])
    token_counts = torch.zeros(n_experts, device=router_logits.device)
    for k in range(expert_indices.shape[-1]):
        token_counts.scatter_add_(
            0, flat_indices[:, k],
            torch.ones(n_tokens, device=router_logits.device)
        )
    f_i = token_counts / (n_tokens * expert_indices.shape[-1])

    # P_i: mean gating probability for each expert
    router_probs = F.softmax(router_logits, dim=-1)  # (B,S,N)
    P_i = router_probs.mean(dim=[0, 1])              # (N,)

    loss = alpha * n_experts * (f_i * P_i).sum()
    return loss
moe_experts.py — Expert Pool & MoE Layer 
class Expert(nn.Module):
    """Single FFN expert with SwiGLU activation (used in Mixtral/LLaMA)."""
    def __init__(self, d_model: int, d_ff: int, dropout: float = 0.0):
        super().__init__()
        self.w1 = nn.Linear(d_model, d_ff, bias=False)   # gate proj
        self.w2 = nn.Linear(d_ff, d_model, bias=False)   # down proj
        self.w3 = nn.Linear(d_model, d_ff, bias=False)   # up proj
        self.dropout = nn.Dropout(dropout)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # SwiGLU: swish(gate) * up, then project down
        gate = F.silu(self.w1(x))
        up   = self.w3(x)
        return self.dropout(self.w2(gate * up))


class MoELayer(nn.Module):
    """
    Full Mixture-of-Experts layer replacing the FFN in a Transformer block.
    Supports efficient batched expert computation.
    """
    def __init__(
        self,
        d_model: int,
        d_ff: int,
        n_experts: int = 8,
        top_k: int = 2,
        dropout: float = 0.0,
    ):
        super().__init__()
        self.n_experts = n_experts
        self.top_k = top_k

        self.router = MoERouter(d_model, n_experts, top_k)
        self.experts = nn.ModuleList([
            Expert(d_model, d_ff, dropout) for _ in range(n_experts)
        ])

    def forward(
        self,
        x: torch.Tensor,         # (B, S, D)
    ) -> Tuple[torch.Tensor, torch.Tensor]:
        B, S, D = x.shape

        # 1. Get routing decisions
        weights, indices, logits = self.router(x, self.training)
        # weights: (B, S, K), indices: (B, S, K)

        # 2. Flatten tokens for batched expert dispatch
        x_flat     = x.reshape(B * S, D)                       # (B*S, D)
        idx_flat   = indices.reshape(B * S, self.top_k)        # (B*S, K)
        wts_flat   = weights.reshape(B * S, self.top_k)        # (B*S, K)

        output = torch.zeros_like(x_flat)                       # (B*S, D)

        # 3. Iterate over top-k slots (efficient for small K)
        for k in range(self.top_k):
            expert_ids = idx_flat[:, k]    # (B*S,)
            expert_wts = wts_flat[:, k]    # (B*S,)

            # Group tokens by their expert assignment
            for e in range(self.n_experts):
                mask = (expert_ids == e)           # boolean mask
                if mask.sum() == 0:
                    continue
                expert_input  = x_flat[mask]       # tokens for this expert
                expert_output = self.experts[e](expert_input)
                output[mask] += expert_wts[mask].unsqueeze(-1) * expert_output

        output = output.reshape(B, S, D)

        # 4. Compute auxiliary loss
        aux = load_balancing_loss(logits, indices, self.n_experts)

        return output, aux
moe_transformer_block.py — Full Block + Training Loop 
class MoETransformerBlock(nn.Module):
    """
    Standard Transformer block with MoE FFN sublayer.
    Collects auxiliary losses during forward pass.
    """
    def __init__(self, d_model: int, n_heads: int, d_ff: int,
                 n_experts: int = 8, top_k: int = 2):
        super().__init__()
        self.norm1  = nn.RMSNorm(d_model)
        self.norm2  = nn.RMSNorm(d_model)
        self.attn   = nn.MultiheadAttention(d_model, n_heads, batch_first=True)
        self.moe    = MoELayer(d_model, d_ff, n_experts, top_k)

    def forward(self, x, attn_mask=None):
        # Attention sub-layer (dense, shared across all tokens)
        normed = self.norm1(x)
        attn_out, _ = self.attn(normed, normed, normed, attn_mask=attn_mask)
        x = x + attn_out

        # MoE FFN sub-layer (sparse, per-token routing)
        normed = self.norm2(x)
        moe_out, aux_loss = self.moe(normed)
        x = x + moe_out

        return x, aux_loss


# ── Training Loop ──────────────────────────────────────────────
def train_step(model, batch, optimizer, aux_weight=0.01):
    optimizer.zero_grad()

    tokens, labels = batch
    logits, aux_losses = model(tokens)    # model aggregates aux from all blocks

    # Language modeling loss
    lm_loss = F.cross_entropy(
        logits.view(-1, logits.size(-1)),
        labels.view(-1),
        ignore_index=-100
    )

    # Total loss: task loss + scaled sum of per-layer aux losses
    total_loss = lm_loss + aux_weight * sum(aux_losses)

    total_loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()

    return {
        "lm_loss": lm_loss.item(),
        "aux_loss": sum(l.item() for l in aux_losses),
        "total": total_loss.item(),
    }
mixtral_inference.py — Using HuggingFace Mixtral / DeepSeek 
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
import torch

# ── Load Mixtral 8×7B (4-bit quantized — fits in ~24GB VRAM) ──
model_id = "mistralai/Mixtral-8x7B-Instruct-v0.1"

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)

tokenizer = AutoTokenizer.from_pretrained(model_id)
model     = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=bnb_config,
    device_map="auto",
    trust_remote_code=True,
)

# ── Inspect router decisions ────────────────────────────────────
# Mixtral's MoE layers are at: model.model.layers[i].block_sparse_moe
moe_layer = model.model.layers[0].block_sparse_moe
print(f"n_experts : {moe_layer.num_experts}")        # 8
print(f"top_k     : {moe_layer.top_k}")              # 2

# ── Hook to capture routing decisions ──────────────────────────
routing_log = []

def routing_hook(module, input, output):
    # output[1] = router logits in HF Mixtral
    routing_log.append(output[1].detach().cpu())

hook = moe_layer.register_forward_hook(routing_hook)

# ── Run inference ──────────────────────────────────────────────
prompt = "Explain how backpropagation works through an MoE layer."
inputs = tokenizer(prompt, return_tensors="pt").to("cuda")

with torch.no_grad():
    output = model.generate(**inputs, max_new_tokens=200, temperature=0.7)

hook.remove()
print(tokenizer.decode(output[0], skip_special_tokens=True))

# ── Fine-tune with LoRA (per-expert adapters) ──────────────────
