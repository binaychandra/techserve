Chapter — Loss Functions in LLMs

The cost of
being wrong

Cross-Entropy Loss is the single number that drives every weight update in a language model. It measures how far a model's predicted distribution is from reality — and converts that distance into a signal for learning.

ℒ = − Σi yi · log(ŷi)

Section 01

What is Cross-Entropy Loss?

Before any equations, the intuition: a language model outputs a probability for every word in its vocabulary. Cross-entropy measures how surprised the model is when it sees the actual next word. Lower surprise = lower loss = better model.

🎲

Entropy (Self-Information)

How unpredictable is a distribution on its own? A coin flip is high entropy. A loaded die is low entropy. Claude's vocabulary distribution starts messy — high entropy.

H(p) = − Σ p(x)·log p(x)
📐

Cross-Entropy

How many bits do you need to encode events from distribution p (truth) using a code optimised for q (model)? The extra cost beyond entropy is the KL divergence — the model's inefficiency.

H(p,q) = − Σ p(x)·log q(x)
🎯

In LLMs: One-Hot Truth

The true label y is one-hot: the correct token gets probability 1.0, all others 0. This collapses the formula to just the log probability of the correct token.

ℒ = − log q(correct token)
🔗

KL Divergence Link

Cross-entropy = Entropy + KL divergence. Since true entropy is fixed, minimising cross-entropy is exactly the same as minimising KL divergence — how far the model is from truth.

H(p,q) = H(p) + DKL(p‖q)
🌡️

Perplexity

Perplexity = eloss. It represents the effective number of equally likely choices the model thinks it has at each token. GPT-2 launched at ~35 PPX. Modern LLMs approach single digits on curated text.

PPL = eℒ
🧮

Why Logarithm?

Log turns multiplied probabilities into summed log-probs (numerically stable). It's convex — so gradient descent reliably reaches the optimum. And it matches information-theoretic bit costs naturally.

log(a·b) = log(a) + log(b)

Section 02

The Mathematics

Step through the full derivation — from raw logits to a scalar loss value that flows gradients backward through billions of parameters.

STEP 1 — LOGITS

The final linear layer produces raw scores (logits) — one per vocabulary token. These have no probabilistic interpretation yet. For GPT-style models the vocab is ~50K tokens; for Llama-3 it's ~128K.

z = Wout · hlast + b    ∈ ℝ|V|
STEP 2 — SOFTMAX

Softmax converts logits into a proper probability distribution. The exponentiation amplifies differences; normalising ensures they sum to 1. Temperature τ controls sharpness — τ→0 gives argmax, τ→∞ gives uniform.

ŷk = softmax(z/τ)k = exp(zk/τ) / Σj exp(zj/τ)
STEP 3 — CROSS-ENTROPY LOSS

For a single token with true label index c, the one-hot ground truth collapses the sum to a single term. This is why CE loss is simply the negative log probability of the correct token.

ℒtoken = − log(ŷc)
STEP 4 — SEQUENCE LOSS

For a sequence of T tokens, CE loss averages over all positions. Each token prediction is independent conditioned on the previous ones — the autoregressive factorisation. This is also called NLL (Negative Log-Likelihood).

ℒseq = − (1/T) Σt=1T log P(xt | x<t; θ)
STEP 5 — GRADIENT (THE MAGIC)

The gradient of CE loss with respect to logits is beautifully simple: predicted probability minus the one-hot indicator. This clean subtraction is why CE + softmax is computationally perfect for classification — no chain rule complexity.

∂ℒ / ∂zk = ŷk − 𝟙[k = c]

Section 04

Loss Variants & When to Use Them

Standard CE loss is the baseline. These are the modifications used across the LLM development lifecycle — from pre-training to RLHF.

Loss Variant Formula / Mechanism Used In Why
Standard CE Loss
−log(ŷc)		 Negative log prob of correct token. Sum or mean over sequence. Pre-training SFT Simple, stable gradients, proven at scale. The default for next-token prediction across all major LLMs.
Label-Smoothed CE
ε=0.1 typical		 Softens one-hot target: 1−ε for correct token, ε/(V−1) for others. Prevents overconfidence. SFT Fine-tuning Reduces over-fitting, improves calibration. Standard in Transformer (2017) paper. Less critical at scale.
Masked CE Loss Applies loss only to non-padding tokens. Mask ignores <PAD> and optionally prompt tokens. SFT Instruction tuning Prevents model from learning to predict padding. In chat fine-tuning, masks the prompt — model only learns to predict the assistant's response.
Weighted CE Loss Per-token weights: wt · (−log ŷt). Higher weight on rare or important tokens. Domain SFT Upweights critical tokens (e.g. code, numbers). Counteracts vocabulary imbalance without resampling data.
SFT + KL Penalty
ℒ = CE + β·DKL		 Adds KL divergence from reference model to CE loss. Constrains drift from base model. RLHF / DPO Prevents reward hacking and catastrophic forgetting. β controls the tradeoff between following SFT signal and staying close to base.
DPO Loss No explicit reward model. Derives policy gradient from preference pairs directly using CE-style log-ratio objective. Alignment Stable, efficient alternative to PPO-based RLHF. Used in Llama-3, Mistral, and most modern alignment pipelines.
GRPO / Group Relative Samples K responses per prompt, uses group reward baseline, maximises advantage-weighted log-probs. Reasoning (CoT) DeepSeek-R1 / Qwen-2.5 approach. Teaches chains of thought by reinforcing high-reward rollouts vs. low-reward ones within a group.
Focal Loss
(1−p)γ·CE		 Down-weights easy (high-confidence) examples. Focuses learning on hard tokens. Experimental Originally for object detection. Sometimes used in LLM SFT to focus on tokens the model finds hard. Not yet standard.

Section 05

Common Pitfalls & Fixes

CE loss is robust, but misuse causes silent failures. These are the mistakes that cost weeks of training runs.

⚠️

Numerical Instability

Never compute softmax then log separately. Catastrophic cancellation occurs. Always use log_softmax + NLLLoss or CrossEntropyLoss (which fuses them).

✅

LogSoftmax Fusion

PyTorch's F.cross_entropy accepts raw logits and computes the log-sum-exp trick internally. Always pass logits, never softmax probabilities.

⚠️

Prompt Loss Contamination

In SFT, computing loss on prompt tokens teaches the model to predict the user query — not the response. This degrades instruction-following quality significantly.

✅

Response-Only Masking

Set labels[prompt_tokens] = -100. PyTorch's CE loss ignores index -100 by default. This ensures gradients only flow from the model's generated tokens.

⚠️

Loss Spike at Step 0

Initial CE loss should be ≈ log(vocab_size) ≈ 10.8 for 50K vocab. A much higher spike means NaN propagation from bad weight init or LR too high.

✅

Warm-Up + Clipping

Use 100–2000 step LR warm-up and gradient clipping (norm ≤ 1.0). Log loss at step 0 as a sanity check. Expected ≈ log(V) confirms correct initialization.

⚠️

Reduction Mode Mismatch

Using reduction='sum' with variable-length sequences scales loss with sequence length, biasing toward longer examples. Gradients become inconsistent across batches.

✅

Mean Reduction

Use reduction='mean' always. For masked losses, compute the mean over non-masked tokens: loss.sum() / mask.sum(). This normalises correctly across batch diversity.

⚠️

Metric vs Loss Confusion

CE loss and perplexity are training signals, not human-quality metrics. A model with lower perplexity can still be less helpful or less truthful — use human eval for downstream quality.

✅

Layered Evaluation

Track CE/PPL during training, use benchmark evals (MMLU, HumanEval) for capability, and RLHF + human ratings for alignment quality. They measure different things.

Section 06

Best Practices — End to End

What the best LLM training teams actually do, in the order you'll encounter it.

1

Pre-Training: Standard CE, No Masking

Use standard cross-entropy loss over all tokens. No label smoothing needed at scale — the data diversity provides implicit regularisation. Pack sequences to full context length to maximise GPU utilisation. Loss is averaged over all non-padding positions.

2

SFT: Masked CE, Response Tokens Only

For instruction tuning, mask the prompt tokens from the loss. Only compute gradients on the assistant's response. Use labels[prompt] = -100. This makes the model learn to generate good completions, not echo user prompts.

3

Always Use Fused Log-Softmax

Use torch.nn.CrossEntropyLoss with raw logits, never manual softmax + log. The internally fused logsumexp is numerically stable across bfloat16 and float16. This is non-negotiable for mixed precision training.

4

Monitor Loss Shape, Not Just Value

A healthy loss curve is smooth and monotonically decreasing with noise. Spikes indicate bad batches or LR issues. A flat plateau signals the model needs more data or a different architecture. Loss oscillating without decreasing often means LR is too high.

5

Post SFT: Move Beyond CE for Alignment

For RLHF and alignment stages, CE alone is insufficient — the model needs preference signal, not just MLE supervision. Transition to DPO (CE-derived log-ratio objective) or PPO with a KL penalty. Keep a reference model frozen; measure KL drift throughout.

6

Perplexity as a Diagnostic, Not a Goal

Lower perplexity means the model predicts held-out text better — useful for comparing checkpoints on the same distribution. Do not optimise perplexity as a proxy for quality. Use downstream task benchmarks (MMLU, GSM8K, HumanEval) for capability measurement.

Pre-Training — Standard CE Loss 
import torch
import torch.nn as nn
import torch.nn.functional as F

# ─── Standard CE Loss for Pre-Training ───────────────────────
# Input:  logits  (B, T, V) — raw outputs from the final linear layer
# Labels: targets (B, T)   — token IDs shifted left by 1 position

def pretrain_loss(logits: torch.Tensor, targets: torch.Tensor) -> torch.Tensor:
    B, T, V = logits.shape
    # Reshape for cross_entropy: (B*T, V) and (B*T,)
    logits  = logits.view(B * T, V)
    targets = targets.view(B * T)
    # PyTorch fuses log-softmax + NLL internally — numerically stable
    loss = F.cross_entropy(logits, targets, reduction='mean')
    return loss

# ─── Shift tokens for causal LM ──────────────────────────────
def causal_lm_loss(logits, input_ids):
    # Model sees tokens[0:T-1], predicts tokens[1:T]
    shift_logits = logits[:, :-1, :].contiguous()
    shift_labels = input_ids[:, 1:].contiguous()
    return pretrain_loss(shift_logits, shift_labels)

# ─── Sanity Check — Initial loss should ≈ log(vocab_size) ────
def check_initial_loss(vocab_size=50257):
    import math
    expected = math.log(vocab_size)  # ≈ 10.82 for GPT-2 vocab
    print(f"Expected initial CE loss: {expected:.3f}")
    return expected
SFT — Masked CE Loss (Response Tokens Only) 
# ─── SFT Masked Loss — only train on assistant response ───────
# loss_mask: 1 where we want gradients, 0 for prompt + padding

def sft_loss(logits, labels, loss_mask):
    """
    logits:    (B, T, V) — model predictions
    labels:    (B, T)    — token IDs (-100 where masked)
    loss_mask: (B, T)    — 1 for response tokens, 0 otherwise
    """
    B, T, V = logits.shape
    shift_logits = logits[:, :-1, :].reshape(-1, V)
    shift_labels = labels[:, 1:].reshape(-1)
    
    # PyTorch ignores index -100 by default (ignore_index=-100)
    loss = F.cross_entropy(
        shift_logits, shift_labels,
        ignore_index=-100,  # masks padding AND prompt tokens
        reduction='sum'
    )
    # Normalise by number of active (non-masked) tokens
    n_active = (shift_labels != -100).sum()
    return loss / n_active.clamp(min=1)

# ─── Build labels with prompt masking ────────────────────────
def build_sft_labels(input_ids, prompt_length):
    labels = input_ids.clone()
    labels[:, :prompt_length] = -100  # Mask prompt positions
    return labels

# ─── Label Smoothing (optional, useful for small datasets) ───
criterion = nn.CrossEntropyLoss(
    label_smoothing=0.1,   # ε = 0.1
    ignore_index=-100
)
DPO Loss — Preference-Based Alignment 
# ─── Direct Preference Optimisation (DPO) Loss ───────────────
# Reformulates RLHF as a classification problem using CE's log-ratio

def dpo_loss(
    policy_chosen_logps,     # log P_θ(y_w | x) — policy on preferred
    policy_rejected_logps,   # log P_θ(y_l | x) — policy on rejected
    ref_chosen_logps,        # log P_ref(y_w | x) — reference on preferred
    ref_rejected_logps,      # log P_ref(y_l | x) — reference on rejected
    beta=0.1               # KL penalty coefficient
):
    # Log-ratio advantage: how much more the policy prefers chosen vs ref
    pi_logratios = policy_chosen_logps - policy_rejected_logps
    ref_logratios = ref_chosen_logps - ref_rejected_logps
    
    # DPO objective: reward difference scaled by beta
    h = beta * (pi_logratios - ref_logratios)
    
    # Cross-entropy-style binary classification loss
    losses = -F.logsigmoid(h)
    
    # Track reward estimates for monitoring
    chosen_rewards   = beta * (policy_chosen_logps - ref_chosen_logps).detach()
    rejected_rewards = beta * (policy_rejected_logps - ref_rejected_logps).detach()
    
    return losses.mean(), chosen_rewards.mean(), rejected_rewards.mean()

# ─── Compute per-token log probabilities ─────────────────────
def get_log_probs(logits, labels, mask):
    log_probs = F.log_softmax(logits, dim=-1)
    chosen    = log_probs.gather(-1, labels.unsqueeze(-1)).squeeze(-1)
    return (chosen * mask).sum(-1) / mask.sum(-1).clamp(min=1)
Perplexity Evaluation + Loss Monitoring 
import math

# ─── Perplexity from Cross-Entropy Loss ──────────────────────
def compute_perplexity(model, dataloader, device):
    model.eval()
    total_loss = 0.0
    total_tokens = 0
    
    with torch.no_grad():
        for batch in dataloader:
            input_ids = batch['input_ids'].to(device)
            labels    = batch['labels'].to(device)
            
            outputs   = model(input_ids)
            logits    = outputs.logits
            
            shift_logits = logits[:, :-1, :].reshape(-1, logits.size(-1))
            shift_labels = labels[:, 1:].reshape(-1)
            
            # Sum (not mean) to accumulate correctly
            loss = F.cross_entropy(
                shift_logits, shift_labels,
                ignore_index=-100, reduction='sum'
            )
            n_tokens = (shift_labels != -100).sum()
            
            total_loss   += loss.item()
            total_tokens += n_tokens.item()
    
    avg_nll    = total_loss / total_tokens
    perplexity = math.exp(avg_nll)
    
    print(f"NLL: {avg_nll:.4f} | Perplexity: {perplexity:.2f}")
    return perplexity

# ─── Training Step with Full Monitoring ──────────────────────
def training_step(model, optimizer, batch, step, log_every=100):
    optimizer.zero_grad()
    
    logits = model(batch['input_ids']).logits
    loss   = causal_lm_loss(logits, batch['input_ids'])
    
    loss.backward()
    
    # Gradient clipping — essential for training stability
    grad_norm = nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    
    optimizer.step()
    
    if step % log_every == 0:
        ppl = math.exp(loss.item())
        print(f"Step {step:6d} | Loss: {loss.item():.4f} | PPL: {ppl:.2f} | GradNorm: {grad_norm:.4f}")
    
    return loss.item()
