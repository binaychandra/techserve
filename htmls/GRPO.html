Group Relative Policy Optimization

How DeepSeek taught models to reason — without a separate critic network

01 The Core Idea

Large language models are pre-trained on next-token prediction. They become good at generating plausible text, but "plausible" ≠ "correct", "reasoned", or "helpful." Post-training alignment techniques push models further — toward outputs that are actually good by some measurable standard.

GRPO (Group Relative Policy Optimization) was introduced by DeepSeek-AI in 2024 as part of the DeepSeekMath and DeepSeek-R1 papers. The key innovation: instead of training a separate critic network (like PPO does), GRPO estimates the advantage of each response by comparing it against a group of sibling responses generated for the same prompt.

Think of it like a classroom exam. The teacher doesn't grade in absolute terms — she ranks students relative to the class average. GRPO does exactly this: each LLM response is scored relative to the mean reward of a group of candidate responses sampled from the same prompt.

This group-relative normalisation eliminates the need for a value function (critic), cutting model complexity and memory while delivering state-of-the-art performance on mathematical and reasoning benchmarks.

02 The Mathematics

2.1 Reward Normalisation — Group Advantage

For a prompt q, the policy samples G output sequences o₁, o₂, …, oG. A reward model (or rule-based scorer) assigns scalar rewards r₁, …, rG. The normalised advantage for the i-th output is:

▸ Group Advantage Estimator
$$\hat{A}_i = \frac{r_i - \mu_r}{\sigma_r + \epsilon}$$
where   μr = mean reward over the group  |  σr = std-dev over the group  |  ε = small constant for numerical stability (e.g. 1e-8)

This replaces the critic/value network V(s) in PPO entirely. No separate model needs to estimate expected future rewards — the group mean serves as the baseline.

2.2 Clipped Surrogate Objective

Like PPO, GRPO uses a probability ratio to measure how much the new policy πθ has shifted from the old sampling policy πθ_old, and clips it to prevent destabilising updates:

▸ Per-token Probability Ratio
$$\rho_t = \frac{\pi_\theta(o_{i,t} \mid q,\, o_{i, πθ = current (updating) policy  |  πθ_old = frozen sampling policy  |  oi,t = t-th token in i-th response
▸ GRPO Surrogate Loss (single response)
$$\mathcal{L}_i^{\text{CLIP}}(\theta) = -\frac{1}{|o_i|}\sum_{t=1}^{|o_i|} \min\!\Bigl(\rho_t\,\hat{A}_i,\;\operatorname{clip}(\rho_t,\,1{-}\varepsilon,\,1{+}\varepsilon)\,\hat{A}_i\Bigr)$$
ε = clip ratio (typically 0.2)  |  |oi| = length of response i

2.3 KL Divergence Penalty

To prevent the policy from drifting too far from the reference model (the frozen pre-trained or SFT checkpoint), a KL term is added to the full objective:

▸ Full GRPO Objective
$$\mathcal{L}^{\text{GRPO}}(\theta) = \frac{1}{G}\sum_{i=1}^{G}\mathcal{L}_i^{\text{CLIP}}(\theta) + \beta\,\mathbb{E}\!\left[\mathrm{KL}\!\left[\pi_\theta \,\|\, \pi_{\text{ref}}\right]\right]$$
β = KL penalty coefficient (e.g. 0.001–0.04)  |  πref = frozen reference / SFT model  |  G = group size (e.g. 8–16 responses per prompt)
Why KL? Without it, RL fine-tuning can cause "reward hacking" — the model exploits the reward signal in ways that are technically high-scoring but semantically broken (e.g., producing very short or repetitive outputs). KL keeps the model grounded to its SFT checkpoint.

2.4 Expanded KL Estimator

The KL term can be computed token-by-token using an unbiased estimator:

▸ Approximated Per-token KL
$$\mathrm{KL}\!\left[\pi_\theta \| \pi_{\text{ref}}\right] \approx \frac{1}{T}\sum_{t=1}^{T}\left(\log\frac{\pi_\theta(o_t)}{\pi_{\text{ref}}(o_t)}\right) = \frac{1}{T}\sum_{t=1}^{T}\left(\log\pi_\theta(o_t) - \log\pi_{\text{ref}}(o_t)\right)$$
This is the per-token log-ratio, averaged over the full response length T

▸ Group Statistics
$$\mu_r = \frac{1.0 + 0.6 + 0.2 + 0.0}{4} = 0.45$$ $$\sigma_r = \sqrt{\frac{(1.0{-}0.45)^2 + (0.6{-}0.45)^2 + (0.2{-}0.45)^2 + (0.0{-}0.45)^2}{4}} \approx 0.354$$
▸ Normalised Advantages
$$\hat{A}_1 = \frac{1.0 - 0.45}{0.354} \approx +1.55$$ $$\hat{A}_2 = \frac{0.6 - 0.45}{0.354} \approx +0.42$$ $$\hat{A}_3 = \frac{0.2 - 0.45}{0.354} \approx -0.71$$ $$\hat{A}_4 = \frac{0.0 - 0.45}{0.354} \approx -1.27$$
Response 1 gets a large positive advantage (+1.55) → policy is pushed to make these tokens more likely. Response 4 gets a large negative advantage (-1.27) → policy is pushed away from this pattern. Responses 2 and 3 get moderate signals.

03 Step-by-Step Algorithm

  1. Prepare SFT Checkpoint as Reference

    Start from a supervised fine-tuned (SFT) model — or even the base model. Freeze it as π_ref. This anchors the KL penalty throughout training.

  2. Sample Group of Responses

    For each prompt q, generate G responses (typically G = 8 to 16) using the current policy π_θ with temperature sampling. Store log-probabilities for each token.

  3. Score with Reward Model

    Pass each response (or response + prompt) through a reward model (or rule-based scorer) to get scalar reward rᵢ. In DeepSeek-R1, rule-based rewards (format check + answer correctness) were used.

  4. Compute Group-Relative Advantages

    Compute group mean μ and std σ. Normalise: Â_i = (r_i − μ) / (σ + ε)

  5. Compute Probability Ratios

    For each token in each response, compute ρ_t = π_θ / π_θ_old using stored log-probs. This is cheap — no second forward pass needed.

  6. Compute Clipped Loss + KL Penalty

    Apply the min-clip surrogate, then add the KL divergence from the reference model. Sum across all tokens in all G responses.

  7. Backpropagate and Update

    Optimise with AdamW. After each gradient step, the old policy is updated to the current policy for the next iteration. Repeat for N epochs or until convergence.

5.3 Dataset Preparation

python · dataset
# GSM8K — grade school math with step-by-step solutions
dataset = load_dataset("openai/gsm8k", "main", split="train")

SYSTEM_PROMPT = """You are a math reasoning assistant.
Think step by step inside <think>...</think> tags,
then give your final answer inside <answer>...</answer> tags."""

def format_prompt(example):
    """Convert dataset row to chat-template format."""
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user",   "content": example["question"]},
    ]
    return {
        "prompt": tokenizer.apply_chat_template(
            messages, tokenize=False, add_generation_prompt=True
        ),
        "answer": example["answer"],  # kept for reward function
    }

dataset = dataset.map(format_prompt)
print(dataset[0]["prompt"][:300])

5.4 Reward Functions (Rule-Based)

GRPO allows multiple reward signals. Here we use two: format correctness and answer accuracy.

python · reward functions
def extract_answer(text: str) -> str:
    """Pull content from <answer>...</answer> tags."""
    m = re.search(r"<answer>(.*?)</answer>", text, re.DOTALL)
    return m.group(1).strip() if m else ""

def extract_ground_truth(answer_str: str) -> str:
    """GSM8K answers end with '#### NUMBER'."""
    m = re.search(r"####\s*([\d,\.\-]+)", answer_str)
    return m.group(1).replace(",", "").strip() if m else ""

# ── Reward 1: format reward (0 or 1) ──────────────────────────
def format_reward(completions, **kwargs) -> list[float]:
    """+1 if response contains both <think> and <answer> tags."""
    rewards = []
    for comp in completions:
        text = comp[0]["content"]
        has_think  = bool(re.search(r"<think>.*?</think>", text, re.DOTALL))
        has_answer = bool(re.search(r"<answer>.*?</answer>", text, re.DOTALL))
        rewards.append(1.0 if (has_think and has_answer) else 0.0)
    return rewards

# ── Reward 2: correctness reward (0 or 2) ─────────────────────
def correctness_reward(completions, answer, **kwargs) -> list[float]:
    """+2 if extracted answer matches ground truth number."""
    rewards = []
    for comp, gt in zip(completions, answer):
        text       = comp[0]["content"]
        pred       = extract_answer(text)
        ground     = extract_ground_truth(gt)
        rewards.append(2.0 if (pred == ground and ground != "") else 0.0)
    return rewards

# Combined reward: max possible = 3.0
REWARD_FUNCTIONS = [format_reward, correctness_reward]

5.5 GRPO Configuration

python · GRPOConfig
config = GRPOConfig(
    # ── Core GRPO hyperparameters ──────────────────────────────
    num_generations=8,        # G — responses per prompt (group size)
    max_new_tokens=512,       # max response length

    # ── KL penalty ───────────────────────────────────────────
    beta=0.01,                # β coefficient for KL divergence

    # ── Training schedule ────────────────────────────────────
    output_dir="./grpo-gsm8k",

    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,  # effective batch = 16
    learning_rate=1e-6,             # keep LR small for RL stability
    warmup_ratio=0.1,
    lr_scheduler_type="cosine",

    # ── Logging & checkpointing ──────────────────────────────
    logging_steps=10,
    save_steps=100,
    report_to="wandb",               # or "none"

    # ── Misc ─────────────────────────────────────────────────
    bf16=True,                       # bfloat16 training
    gradient_checkpointing=True,     # save activation memory

5.8 Manual GRPO Loss — Pure NumPy (educational)

To fully demystify the math, here is the GRPO loss computed from scratch with NumPy — no frameworks needed.

python · manual grpo loss
import numpy as np

def grpo_loss_manual(
    log_probs_new: np.ndarray,   # shape (G, T) — new policy log P
    log_probs_old: np.ndarray,   # shape (G, T) — old policy log P
    log_probs_ref: np.ndarray,   # shape (G, T) — reference log P
    rewards:       np.ndarray,   # shape (G,)   — scalar reward per response
    eps:  float = 0.2,          # clip ratio ε
    beta: float = 0.01,         # KL penalty coefficient β
):
    G, T = log_probs_new.shape

    # ── Step 1: group-relative advantage ─────────────────────
    mu    = rewards.mean()
    sigma = rewards.std() + 1e-8
    A_hat = (rewards - mu) / sigma             # shape (G,)
    A_hat = A_hat[:, np.newaxis]               # broadcast to (G, 1)

    # ── Step 2: probability ratio per token ──────────────────
    rho = np.exp(log_probs_new - log_probs_old)  # (G, T)

    # ── Step 3: clipped surrogate ─────────────────────────────
    rho_clip   = np.clip(rho, 1 - eps, 1 + eps)
    surrogate1 = rho      * A_hat              # (G, T)
    surrogate2 = rho_clip * A_hat              # (G, T)
    clip_loss  = -np.minimum(surrogate1, surrogate2).mean()

    # ── Step 4: KL divergence (per-token, averaged) ──────────
    kl_per_token = log_probs_new - log_probs_ref  # (G, T)
    kl_mean      = kl_per_token.mean()

    # ── Step 5: total GRPO loss ───────────────────────────────
    total_loss = clip_loss + beta * kl_mean

    return {
        "total_loss": total_loss,
        "clip_loss":  clip_loss,
        "kl_penalty": kl_mean,
        "advantages": A_hat.squeeze(),
    }


# ── Quick demo with random values ─────────────────────────────
np.random.seed(42)
G, T = 4, 50   # 4 responses, 50 tokens each

results = grpo_loss_manual(
    log_probs_new = np.random.randn(G, T) * 0.1 - 3.0,
    log_probs_old = np.random.randn(G, T) * 0.1 - 3.0,
    log_probs_ref = np.random.randn(G, T) * 0.1 - 3.0,
    rewards       = np.array([1.0, 0.6, 0.2, 0.0]),
)

for k, v in results.items():
    print(f"{k:<14} → {v}")

07 Practical Tips & Common Pitfalls

✅ What works well

Use rule-based rewards when possible. Format checks and answer-correctness verifiers are cheap, accurate, and free from reward model bias. DeepSeek-R1 used only two rules: correctness and format.
Diversity in the group matters. If the policy is already very confident (low temperature → all G responses identical), advantages collapse to zero and no gradient flows. Keep temperature high enough (0.7–1.0) to maintain response diversity within the group.
Start with a strong SFT model. GRPO is a fine-tuning step, not a training-from-scratch method. A good SFT baseline produces more useful groups to compare.

⚠️ Pitfalls

Reward collapse (all rewards equal). If your reward function is too coarse (e.g., binary 0/1 with a model that's already near-perfect), σ → 0 and all advantages → 0. Add a smooth partial-credit signal.
KL runaway. If β is too small, the model can rapidly diverge from the reference, producing incoherent text. Monitor KL divergence during training; typical safe range is 0.5–4.0 nats per token.
Long-context instability. GRPO generates G full responses per step. At G=8 with 512-token outputs, GPU memory scales quickly. Use gradient checkpointing, Flash Attention 2, and LoRA/QLoRA adapters for memory savings.

∑ Summary

GRPO is an elegant simplification of PPO that removes the critic network by using the within-group reward distribution as its own baseline. The key equations:
