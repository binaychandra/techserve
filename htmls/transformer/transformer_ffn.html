01 — The Problem

What gap does the FFN fill?

At this point in your Transformer journey, you've seen self-attention — it lets tokens look at each other and decide what to focus on. That's brilliant. But attention alone has a critical gap.

🚨 The limitation of attention

Attention is great at routing information — deciding which tokens matter. But it does almost no deep transformation of that information. It's mostly weighted averaging. We need something that can learn complex, non-linear relationships between features.

Attention does

Routing — "which other tokens are relevant to me?" It mixes information across positions. Largely linear (softmax aside).

FFN does

Transformation — "given this mixed context, what do I actually know?" Deep non-linear processing per token. The model's real "thinking" happens here.

FFN as memory

Research shows FFN layers act as key-value memories. They store and recall factual knowledge — like "Paris is the capital of France."

Why non-linearity?

Without activation functions, stacking linear layers is equivalent to one linear layer. Non-linearity unlocks the ability to learn any function.

💡

Rule of thumb: Attention = communication between tokens. FFN = computation for each token independently. Together they form the complete Transformer block.

02 — Build the Intuition

A dead-simple analogy

Imagine a team meeting. During the meeting (attention), everyone listens to each other and collects notes. Then the meeting ends, and each person goes to their desk (FFN) to process what they heard — cross-referencing with their own knowledge and drawing conclusions.

The FFN is that private desk-work. It takes a single token's enriched representation and runs it through a two-layer neural network — expand, activate, compress — entirely independently for each token position.

🏋️

The 4× expansion trick: The hidden layer is intentionally much wider than the input. In the original paper, d_model = 512 expanded to d_ff = 2048. This creates a rich intermediate space where the model can learn nuanced feature interactions, then compress the insights back down.

03 — The Architecture

Two linear layers, one activation

The FFN is beautifully simple in structure. For each token independently:

FFN(x) = W₂ · activation( W₁x + b₁ ) + b₂

That's it. Two weight matrices, two bias vectors, one non-linear activation in the middle.

Position-wise independence: Unlike attention, the FFN processes each token completely independently. The same weight matrices W₁ and W₂ are applied to every token position — like running the same small MLP across each position in parallel.

04 — Activation Functions

The non-linearity that makes it work

The activation function is the key that unlocks non-linear learning. Without it, stacking two linear layers would collapse to just one. Let's explore the most common choices interactively.

05 — Walk Through the Math

A concrete numerical example

Let's trace a tiny example end-to-end. Input dimension d_model = 4, hidden dimension d_ff = 8 (2× for clarity).

Start with a single token's embedding after attention:

x = [1.0, -0.5, 2.0, 0.3] # shape: (4,)
01

First linear layer: expand to d_ff

Multiply by weight matrix W₁ (shape: 8×4) and add bias b₁ (shape: 8).

h = W₁ @ x + b₁ # shape: (8,) h ≈ [1.2, -0.8, 3.1, 0.4, -1.1, 2.2, 0.7, -0.3]
02

Apply GELU activation

Each element is passed through GELU. Positive values pass; near-zero and negative values are partially suppressed.

h_act = GELU(h) h_act ≈ [1.07, -0.17, 3.09, 0.26, -0.15, 2.19, 0.47, -0.07]

Notice how −0.8 becomes −0.17 (softly suppressed, not killed like ReLU would do).

03

Second linear layer: compress back to d_model

Multiply by W₂ (shape: 4×8) and add bias b₂ (shape: 4).

y = W₂ @ h_act + b₂ # shape: (4,) y ≈ [0.82, -0.14, 1.73, 0.55]
04

Add & LayerNorm (wraps the whole FFN)

The output y is residually added to the original input x, then layer-normalised — just like we covered in Chapter 3!

output = LayerNorm(x + y)

07 — Python Implementation

From scratch to production

Three versions: pure NumPy (to understand the mechanics), then PyTorch from scratch, then the clean module you'd actually use in a project.

ffn_numpy.py — building blocks
import numpy as np
from scipy.special import erf   # for GELU

# ─── Activation functions ──────────────────────────────
def relu(x):
    """max(0, x) — simple, fast, can die for x < 0"""
    return np.maximum(0, x)

def gelu(x):
    """Gaussian Error Linear Unit — smooth, used in BERT/GPT"""
    return 0.5 * x * (1 + erf(x / np.sqrt(2)))

def silu(x):
    """Sigmoid Linear Unit (Swish) — x * sigmoid(x), used in LLaMA"""
    return x / (1 + np.exp(-x))


# ─── Feed Forward Network (from scratch) ───────────────
class FeedForward:
    def __init__(self, d_model: int, d_ff: int = None, activation=gelu):
        """
        Args:
            d_model    : embedding / model dimension (e.g. 512)
            d_ff       : hidden dimension (default: 4 * d_model)
            activation : any function f: ndarray -> ndarray
        """
        d_ff = d_ff or 4 * d_model

        # Xavier initialisation — keeps variance stable
        scale1 = np.sqrt(2.0 / (d_model + d_ff))
        scale2 = np.sqrt(2.0 / (d_ff + d_model))

        self.W1  = np.random.randn(d_ff, d_model) * scale1    # (d_ff, d_model)
        self.b1  = np.zeros(d_ff)                              # (d_ff,)
        self.W2  = np.random.randn(d_model, d_ff) * scale2    # (d_model, d_ff)
        self.b2  = np.zeros(d_model)                           # (d_model,)
        self.act = activation

    def __call__(self, x: np.ndarray) -> np.ndarray:
        """
        x shape: (seq_len, d_model)  OR  (d_model,) for single token
        """
        h   = x @ self.W1.T + self.b1    # (..., d_ff)   — linear expand
        h   = self.act(h)                 # (..., d_ff)   — non-linearity
        out = h @ self.W2.T + self.b2    # (..., d_model)— linear compress
        return out


# ─── Demo ──────────────────────────────────────────────
d_model = 8
ffn = FeedForward(d_model=d_model, activation=gelu)

# Process a sequence of 5 tokens
x      = np.random.randn(5, d_model)
output = ffn(x)

print(f"Input  shape: {x.shape}")      # (5, 8)
print(f"Output shape: {output.shape}")  # (5, 8) — same shape!
print(f"Input  mean/std: {x.mean():.3f} / {x.std():.3f}")
print(f"Output mean/std: {output.mean():.3f} / {output.std():.3f}")
ffn_pytorch.py — production module
import torch
import torch.nn as nn
import torch.nn.functional as F


# ──────────────────────────────────────────────────────
#  Standard FFN  (original Transformer / BERT / GPT-2)
# ──────────────────────────────────────────────────────
class FeedForward(nn.Module):
    @staticmethod
    def gelu(x): return F.gelu(x)

    def __init__(
        self,
        d_model:   int,
        d_ff:      int   = None,
        activation: str  = "gelu",  # "relu" | "gelu" | "silu"
        dropout:   float = 0.1,
        bias:      bool  = True,
    ):
        super().__init__()
        d_ff = d_ff or 4 * d_model

        # Two linear projections
        self.linear1 = nn.Linear(d_model, d_ff, bias=bias)
        self.linear2 = nn.Linear(d_ff, d_model, bias=bias)
        self.dropout = nn.Dropout(p=dropout)

        _acts = {"relu": nn.ReLU(), "gelu": nn.GELU(), "silu": nn.SiLU()}
        self.activation = _acts[activation]

        # Initialise weights — same trick as GPT-2
        nn.init.normal_(self.linear1.weight, std=0.02)
        nn.init.normal_(self.linear2.weight, std=0.02)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """
        x : (batch, seq_len, d_model)
        returns (batch, seq_len, d_model)
        """
        x = self.linear1(x)      # → (B, S, d_ff)
        x = self.activation(x)   # non-linearity
        x = self.dropout(x)      # regularisation
        x = self.linear2(x)      # → (B, S, d_model)
        return x


# ──────────────────────────────────────────────────────
#  SwiGLU FFN  (LLaMA-2/3, PaLM, Gemma)
#  Uses gating for richer expressivity.
#  Note: d_ff is ~8/3 * d_model (not 4x) to keep param count equal.
# ──────────────────────────────────────────────────────
class SwiGLUFeedForward(nn.Module):
    def __init__(self, d_model: int, d_ff: int = None):
        super().__init__()
        # 8/3 * d_model, rounded to nearest multiple of 256
        d_ff = d_ff or int(8 * d_model / 3 / 256 + 1) * 256

        self.gate_proj  = nn.Linear(d_model, d_ff, bias=False)  # W_gate
        self.up_proj    = nn.Linear(d_model, d_ff, bias=False)  # W_up
        self.down_proj  = nn.Linear(d_ff, d_model, bias=False)  # W_down

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # SiLU(W_gate·x)  ⊙  W_up·x
        gate = F.silu(self.gate_proj(x))   # gating signal
        up   = self.up_proj(x)               # value signal
        return self.down_proj(gate * up)     # element-wise gate, then project


# ─── Quick test ────────────────────────────────────────
batch, seq, d_model = 2, 16, 512

ffn_swiglu   = SwiGLUFeedForward(d_model=d_model)

transformer_encoder_layer.py — full block
import torch
import torch.nn as nn

# ──────────────────────────────────────────────────────
#  Complete Encoder Layer showing where FFN sits
# ──────────────────────────────────────────────────────
class TransformerEncoderLayer(nn.Module):
    """
    One full encoder block:
        Pre-LN Self-Attention  →  Add
        Pre-LN Feed-Forward    →  Add
    """
    def __init__(
        self,
        d_model:   int   = 512,
        nhead:     int   = 8,
        d_ff:      int   = 2048,  # 4 × d_model
        dropout:   float = 0.1,
        activation: str  = "gelu",
    ):
        super().__init__()

        # ── Sub-layer 1: Multi-Head Self-Attention ──
        self.attn     = nn.MultiheadAttention(d_model, nhead, batch_first=True, dropout=dropout)
        self.norm1    = nn.LayerNorm(d_model)
        self.dropout1 = nn.Dropout(dropout)

        # ── Sub-layer 2: Feed-Forward Network ──────
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU() if activation == "gelu" else nn.ReLU(),
            nn.Dropout(dropout),
            nn.Linear(d_ff, d_model),
        )
        self.norm2    = nn.LayerNorm(d_model)
        self.dropout2 = nn.Dropout(dropout)

    def forward(
        self,
        x:           torch.Tensor,               # (B, S, d_model)
        attn_mask:   torch.Tensor = None,
        key_padding_mask: torch.Tensor = None,
    ) -> torch.Tensor:

        # ── Pre-LN Attention block ────────────────
        x_norm = self.norm1(x)
        attn_out, _ = self.attn(x_norm, x_norm, x_norm,
                                 attn_mask=attn_mask,
                                 key_padding_mask=key_padding_mask)
        x = x + self.dropout1(attn_out)   # residual Add

        # ── Pre-LN FFN block ──────────────────────
        x_norm = self.norm2(x)            # normalise first (Pre-LN)
        ffn_out = self.ffn(x_norm)        # ← Feed Forward happens here
        x = x + self.dropout2(ffn_out)   # residual Add

        return x                           # (B, S, d_model)


# ─── Verify ────────────────────────────────────────────
layer  = TransformerEncoderLayer(d_model=512, nhead=8, d_ff=2048)
x      = torch.randn(2, 20, 512)  # batch=2, seq=20 tokens
output = layer(x)

params = sum(p.numel() for p in layer.parameters())
ffn_p  = sum(p.numel() for p in layer.ffn.parameters())

print(f"Block output : {output.shape}")             # (2, 20, 512)
print(f"Total params : {params:,}")                 # ~3.15M
print(f"FFN params   : {ffn_p:,} ({ffn_p/params:.0%})") # ~67% — FFN dominates!
🔬

Fun fact — FFN dominates parameter count: In a standard Transformer encoder layer, the FFN accounts for roughly ~66% of all parameters in that layer. The attention mechanism is parameter-light; the FFN is where most of the model's knowledge is stored.
