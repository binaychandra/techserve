01 — The Problem

Attention has no sense of order

Self-attention computes relationships between every pair of tokens simultaneously. But the mechanism is permutation-invariant — it treats the input as a set, not a sequence. Without extra information, "Dog bites man" and "Man bites dog" look identical to the model.

⚡ The Permutation Problem

These two sentences have opposite meanings, but pure self-attention sees the same bag of tokens:

"Dog"
"bites"
"Man"
≡
"Man"
"bites"
"Dog"
←
same attention weights!
// Without position info: both produce identical attention patterns
02 — The Formula

Sine & Cosine Encoding

Each position gets a unique vector built from sinusoidal functions at different frequencies. The "Attention Is All You Need" paper defines it as:

PE(pos, 2i) = sin( pos / 100002i/d_model )
PE(pos, 2i+1) = cos( pos / 100002i/d_model )
// even dimensions → sine | odd dimensions → cosine
posPosition of token in sequence (0, 1, 2, …)
iDimension index of the encoding vector
d_modelTotal embedding dimension (e.g. 512)
10000Scaling constant — controls frequency spread

The final input to the Transformer is simply:

Input = Embedding(token) + PE(pos)

Position encoding is added directly to the token embedding — no extra parameters needed.

Live Visualization — Sinusoidal Waves across Positions

Each colored wave = one dimension of the PE vector. Low-frequency waves capture broad position; high-frequency ones capture fine-grained order.

03 — Intuition

Why sinusoids?

There are many ways to encode position (learned, one-hot, index). Sinusoids were specifically chosen for elegant mathematical properties.

📡

Every Position is Unique

Because multiple frequencies are combined (like binary clock hands), no two positions produce the same vector — even for very long sequences.

🔗

Relative Distance is Learnable

PE(pos + k) can be expressed as a linear function of PE(pos). This means the model can learn to attend to "the token 3 positions back" rather than just absolute positions.

📏

Bounded Values

sin/cos always stay in [−1, +1]. No explosion of values, no vanishing — the encoding stays numerically well-behaved no matter how long the sequence is.

🔢

The Binary Clock Analogy

Think of it like binary digits: the lowest bit flips every step, the next every 2 steps, etc. Sinusoids do the same — lowest dim oscillates fast, highest dim oscillates slowly.

🚫

No Extra Parameters

It's a deterministic function — nothing to learn, nothing to overfit. The model gets position information for free, even for sequences longer than training data.

⚡

Parallel Computation

Unlike RNNs which must process tokens one-by-one to build up sequential context, PE is added all at once — enabling full parallelism.

04 — Advantages

Why not other approaches?

❌ Alternative Approaches

  • One-hot encoding: doesn't scale to long sequences
  • Integer index (pos/N): arbitrary scale, poor generalisation
  • Learned positional: can't extrapolate beyond training length
  • RNN sequential: breaks parallelism, slow to train
  • Convolution: limited receptive field for distant tokens

✅ Sinusoidal PE Wins

  • Generalizes to unseen sequence lengths naturally
  • Bounded and numerically stable at all positions
  • Zero extra parameters — no added training cost
  • Preserves relative distance information geometrically
  • Works with fully parallel forward pass (no recurrence)
  • 01
    Extrapolation to Longer Sequences At inference time, you can feed sequences longer than training. PE(1000) is just as valid as PE(50) — the formula works forever.
  • 02
    Linear Relative Position via Dot Products The dot product PE(pos) · PE(pos+k) depends only on k (not pos). Attention scores naturally reflect relative distance — elegant and powerful.
  • 03
    Smooth Gradient Flow The smooth, continuous nature of sin/cos (vs. discrete one-hot) allows gradients to flow cleanly during backpropagation through the embedding layer.
  • 04
    Dimensionality Matches Embedding PE has the same d_model dimensions as the token embedding — addition is clean, no projection needed, no dimensionality mismatch.
05 — Worked Example

Encoding "The cat sat"

Let's walk through exactly what happens when we encode a 3-token sentence with a tiny d_model = 8.

"The  cat  sat"
Token pos PE dims (d=0..7) Meaning
"The" 0 [sin(0), cos(0), sin(0), cos(0), …]
= [0.000, 1.000, 0.000, 1.000, …]		 pos=0: all sines are 0, all cosines are 1. Unique "start" signature.
"cat" 1 [sin(1), cos(1), sin(0.01), cos(0.01), …]
= [0.841, 0.540, 0.010, 1.000, …]		 First dims oscillate fast; last dims barely moved from pos=0.
"sat" 2 [sin(2), cos(2), sin(0.02), cos(0.02), …]
= [0.909, −0.416, 0.020, 1.000, …]		 Clearly distinct from pos=1. Model can tell these apart.
PE Heatmap — values for "The cat sat" across 8 dimensions

🔵 dark = negative  |  🟡 bright = positive  |  Each column = one PE dimension  |  Each row = one token position

The final vector fed into the first Transformer layer for "cat" (pos=1) is:

Input[1] = Embed("cat") + PE(1)

// e.g., d_model = 8:
Embed("cat") = [0.21, −0.14, 0.87, 0.33, 0.05, −0.62, 0.11, 0.48]
PE(1) = [0.84, 0.54, 0.01, 1.00, 0.00, 1.00, 0.00, 1.00]
───────────────────────────────────────
Input[1] = [1.05, 0.40, 0.88, 1.33, 0.05, 0.38, 0.11, 1.48]

This combined vector carries both the semantic meaning of "cat" and the positional fact that it is the 2nd token in the sequence.
