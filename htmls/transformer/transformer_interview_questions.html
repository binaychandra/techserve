Q01 What is the Transformer model and why was it introduced?
+

The Transformer is a deep learning architecture introduced in the 2017 paper "Attention Is All You Need" by Vaswani et al. at Google. It was designed to overcome the main limitations of RNNs and LSTMs for sequence-to-sequence tasks.

  • RNN problem: RNNs process tokens sequentially, making parallelization impossible and causing vanishing/exploding gradients over long sequences.
  • Transformer solution: Uses self-attention to relate all tokens to each other simultaneously — enabling full parallelism during training.
  • Originally built for machine translation, it has since become the backbone of LLMs (GPT, BERT, T5, etc.).
The name "transformer" refers to the way it transforms an input sequence into an output sequence via learned attention patterns.
Q02 What is self-attention, and how does it differ from regular attention?
+

Regular (cross) attention computes attention between two different sequences — e.g., an encoder's output and a decoder's input (as in seq2seq). Self-attention computes attention within a single sequence: every token attends to every other token in the same sequence.

This allows each token to build a contextual representation by aggregating information from all other relevant tokens, regardless of distance.

Output_i = Σ_j softmax(Q_i · K_j / √d_k) · V_j
  • Q (Query) — what this token is looking for
  • K (Key) — what each token offers to be found
  • V (Value) — the actual content to aggregate
Q03 What are the main components of a Transformer block?
+

A single Transformer block (or layer) contains:

  • Multi-Head Self-Attention (MHSA) — attends across all token positions
  • Add & Norm — residual connection + LayerNorm after attention
  • Feed-Forward Network (FFN) — two linear layers with a non-linearity (GELU or ReLU)
  • Add & Norm — residual connection + LayerNorm after FFN

The encoder stack is these two sub-layers. The decoder adds a third: cross-attention over encoder output.

Q04 Why do we need positional encoding?
+

Self-attention is permutation-invariant — it has no inherent notion of token order. Without positional information, "dog bites man" and "man bites dog" would produce identical representations.

Positional encodings inject order information. The original paper uses sinusoidal encodings:

PE(pos, 2i) = sin(pos / 10000^(2i/d_model)) PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))

These are added element-wise to token embeddings. Modern models like RoPE (Rotary Position Embedding) and ALiBi learn or compute positional information differently.

Q05 What is the role of the Feed-Forward layer in a Transformer?
+

The FFN applies a two-layer MLP to each position independently and identically:

FFN(x) = max(0, xW₁ + b₁)W₂ + b₂ [original: ReLU] FFN(x) = GELU(xW₁ + b₁)W₂ + b₂ [modern variants]

The hidden dimension is usually 4× the model dimension (e.g., 4096 hidden for a 1024-dim model). Research suggests the FFN acts as a key-value memory storing factual associations learned during training, complementing the attention mechanism's relational reasoning.

Q06 What is the difference between encoder-only, decoder-only, and encoder-decoder Transformers?
+
  • Encoder-only (e.g., BERT) — bidirectional; every token attends to all others. Best for understanding tasks: classification, NER, QA.
  • Decoder-only (e.g., GPT, LLaMA) — causal (left-to-right) masked attention; each token only attends to past tokens. Best for text generation / autoregressive tasks.
  • Encoder-decoder (e.g., T5, BART) — encoder reads full input, decoder generates output attending to encoder states via cross-attention. Best for translation, summarization, seq2seq.
Most modern LLMs (GPT-4, LLaMA, Mistral) are decoder-only due to simplicity and scaling efficiency.
Q07 What is Layer Normalization and why is it used in Transformers?
+

LayerNorm normalizes the activations across the feature dimension (not the batch dimension like BatchNorm):

LayerNorm(x) = γ · (x − μ) / (σ + ε) + β

Benefits in Transformers:

  • Stabilizes training of very deep networks
  • Works well with variable-length sequences (unlike BatchNorm)
  • Enables larger learning rates

Modern variants: Pre-LN (applies norm before the sub-layer) is now preferred over Post-LN for stability in very deep models. RMSNorm (used in LLaMA) is a simpler variant that drops the mean subtraction.

Q08 What is tokenization and why does it matter for Transformers?
+

Tokenization converts raw text into integer IDs that the model processes. The Transformer never sees raw characters — only token IDs looked up in an embedding matrix.

  • BPE (Byte Pair Encoding) — used by GPT-2/4; merges frequent character pairs iteratively
  • WordPiece — used by BERT; similar but maximizes likelihood
  • SentencePiece — language-agnostic, used by T5/LLaMA

Tokenization quality directly impacts model performance: a poor vocabulary forces the model to represent common words with multiple tokens, wasting context window capacity and degrading arithmetic / coding ability.

GPT-4 uses ~100K vocab tokens via tiktoken. LLaMA 3 uses 128K. Larger vocab = fewer tokens per word = more efficient context usage.
Intermediate
Q09 Explain Multi-Head Attention. Why use multiple heads?
+

Multi-Head Attention runs h independent attention heads in parallel, each with its own Q, K, V projection matrices of dimension d_k = d_model / h:

MultiHead(Q,K,V) = Concat(head₁, ..., headₕ) · Wᴼ headᵢ = Attention(Q·Wᵢᴼ, K·Wᵢᴷ, V·Wᵢᵛ)

Why multiple heads?

  • Each head can learn to attend to different types of relationships simultaneously (syntax, coreference, semantics, position)
  • Provides richer representational capacity than a single wider attention
  • Interpretability research shows different heads specialize (e.g., heads that track subject-verb agreement vs. co-reference)

The outputs of all heads are concatenated and projected back to d_model via Wᴼ.

Q10 What is the computational complexity of self-attention, and why is it a bottleneck?
+

Standard self-attention is O(n² · d) in time and O(n²) in memory, where n is sequence length and d is model dimension.

This quadratic bottleneck means:

  • Doubling context length → 4× compute and memory for the attention matrix
  • At n=100K tokens, the attention matrix alone is ~40GB in float32

Solutions include:

  • Flash Attention — kernel fusion + tiling to avoid materializing the full matrix; same result, O(n) memory
  • Sparse Attention — attend only to a local window or fixed global tokens (Longformer, BigBird)
  • Linear Attention — kernel trick approximation (Performer, RWKV)
  • GQA / MQA — group/multi-query attention reduces KV cache size
Q11 What is the KV Cache, and how does it speed up inference?
+

During autoregressive generation, each new token needs to attend to all previous tokens. Without a cache, we'd recompute all K and V projections from scratch for every decoding step — O(n²) total work.

The KV Cache stores the Key and Value tensors for all previously generated tokens. At each step, we only compute K and V for the new token and append to the cache:

  • Reduces per-step attention cost from O(n·d) → O(1) new projections
  • Memory cost: 2 × n_layers × n_heads × d_head × sequence_length × bytes_per_element
  • At long contexts, KV cache can exceed model weight size — motivating GQA, quantized KV caches, and sliding window attention
For LLaMA 3 70B at 128K context in float16, the KV cache is ~137GB — larger than the model itself.
Q12 What is the difference between BERT and GPT pre-training objectives?
+
  • BERT (Masked Language Modeling) — randomly masks 15% of tokens and trains the model to predict them using full bidirectional context. Also uses Next Sentence Prediction (NSP). Produces strong contextual embeddings for understanding tasks.
  • GPT (Causal Language Modeling) — predicts the next token given all previous tokens. Autoregressive; uses causal masking. Naturally suited for generation.

Key practical difference: BERT cannot generate text (it sees future tokens during training), while GPT cannot naturally leverage right-side context. T5 unifies both via a text-to-text format with masked span prediction.

Q13 What is Rotary Positional Embedding (RoPE), and why is it preferred in modern LLMs?
+

RoPE encodes position by rotating Query and Key vectors in a 2D plane by an angle proportional to the token's absolute position. The key insight: the dot product Q·K then depends only on their relative positions.

RoPE(x, pos) = x · [cos(mθ) + i·sin(mθ)] (complex notation)

Why preferred over learned or sinusoidal encodings:

  • Naturally encodes relative positions — crucial for length generalization
  • No extra parameters beyond the rotation angle
  • Enables context extension via RoPE scaling (YaRN, NTK-aware), allowing models trained at 4K to generalize to 128K+ context
  • Used in LLaMA, Mistral, Qwen, Falcon, and most modern open-weight LLMs
Q14 What is Grouped Query Attention (GQA) and how does it differ from MHA and MQA?
+
  • MHA (Multi-Head Attention) — each of h heads has its own Q, K, V. Full expressiveness, highest memory.
  • MQA (Multi-Query Attention) — all heads share a single K and V (only Q is per-head). Fastest inference, smallest KV cache, but sometimes quality degradation.
  • GQA (Grouped Query Attention) — heads are partitioned into G groups; heads in the same group share K and V. A sweet spot between MHA and MQA.
KV cache size ratio: MHA=1x, GQA=G/h, MQA=1/h

GQA (used in LLaMA 3, Mistral, Gemma) typically uses G=8 groups for 32 heads, giving 4× KV cache reduction with negligible quality loss.

Q15 What is Flash Attention and why is it important?
+

Flash Attention (Dao et al., 2022) is an IO-aware, exact attention algorithm. It produces mathematically identical results to standard attention, but is dramatically faster and more memory-efficient.

Key ideas:

  • Tiling — splits Q, K, V into blocks that fit in fast SRAM (on-chip) rather than the slow HBM (GPU DRAM)
  • Online softmax — computes the softmax incrementally without materializing the full n×n attention matrix
  • Reduces HBM reads/writes from O(n²) to O(n), achieving 2-4× speedup on A100s
  • Memory usage drops from O(n²) to O(n)

Flash Attention 2 & 3 extended this with better GPU utilization and support for MQA/GQA, and are now standard in all major LLM frameworks.

Q16 What is the Scaling Laws insight and why does it matter?
+

The Neural Scaling Laws paper (Kaplan et al., 2020) and the Chinchilla paper (Hoffmann et al., 2022) showed that LLM performance follows predictable power laws as you scale compute, parameters, and data.

Chinchilla's key finding: for a given compute budget C (FLOPs), the optimal strategy is:

N_optimal ∝ C^0.5 (model parameters) D_optimal ∝ C^0.5 (training tokens) Rule of thumb: ~20 tokens per parameter
  • GPT-3 (175B params, 300B tokens) was undertrained by Chinchilla standards
  • Chinchilla (70B, 1.4T tokens) outperformed much larger undertrained models
  • This shifted the field toward training smaller models on more data: LLaMA, Mistral, Phi
Advanced
Q17 How does Mixture of Experts (MoE) work in Transformers?
+

In a Sparse MoE Transformer, the FFN layer is replaced with E expert FFNs, but only top-k (typically k=2) experts are activated per token via a gating network:

MoE(x) = Σᵢ∈TopK G(x)ᵢ · Expertᵢ(x) G(x) = Softmax(TopK(x · Wg, k))

Benefits:

  • Parameter efficiency — Mixtral 8x7B has 47B total params but only ~13B active per token
  • Same inference cost as a ~13B dense model with the capacity of 47B
  • Experts can specialize in different domains/skills

Challenges: load balancing (preventing expert collapse where all tokens route to same expert), auxiliary load balancing loss, and higher memory requirements since all expert weights must be loaded.

Q18 Explain the RLHF pipeline (Reinforcement Learning from Human Feedback).
+

RLHF aligns a pre-trained LLM with human preferences through three stages:

  • Stage 1 — SFT (Supervised Fine-Tuning): Fine-tune the base model on curated demonstration data (human-written ideal responses).
  • Stage 2 — Reward Model (RM): Train a separate model to score outputs based on human preference comparisons. Given two responses A and B, humans label which is better; the RM learns to predict that ranking.
  • Stage 3 — RL via PPO: Use PPO (Proximal Policy Optimization) to fine-tune the SFT model to maximize the RM score, with a KL divergence penalty to prevent the policy from drifting too far from the SFT model.
Reward = RM(response) − β · KL(π_RL || π_SFT)

Modern alternatives: DPO (Direct Preference Optimization) eliminates the separate RM by analytically solving the RLHF optimization, making it simpler and more stable. Used by LLaMA 3, Mistral Instruct.

Q19 What is speculative decoding and how does it accelerate inference?
+

Speculative decoding (Leviathan et al., 2023) uses a small fast draft model to speculatively generate k tokens, then verifies them in a single forward pass of the large target model.

Key insight: the large model can evaluate k tokens in parallel (unlike serial autoregressive decoding) with the same compute as a single token step if the KV cache is managed correctly.

  • If all k draft tokens are accepted → k-token speedup for 1 forward pass cost
  • If draft diverges at position j → reject tokens j..k and resample from the target distribution at position j
  • Output distribution is identical to the target model (not an approximation)
  • Typical speedup: 2-3× for code/repetitive text; less for creative tasks
Self-speculative decoding (Medusa, draft-and-verify within same model using auxiliary heads) avoids needing a separate draft model.
Q20 What is LoRA and how does it enable efficient fine-tuning?
+

LoRA (Low-Rank Adaptation) freezes the pre-trained model weights and injects trainable rank-decomposition matrices into each target layer:

W' = W₀ + ΔW = W₀ + B·A B ∈ ℝ^(d×r), A ∈ ℝ^(r×k), r << min(d,k)

A is initialized randomly (often Kaiming uniform), B is initialized to zero so ΔW=0 at the start. Only A and B are trained — typically 0.1–1% of total parameters.

  • QLoRA — further quantizes frozen weights to 4-bit NF4 while keeping adapters in bfloat16. Enables fine-tuning 70B models on a single A100.
  • Common target modules: Q, K, V, O projections in attention; increasingly MLP layers too for reasoning tasks.
  • Rank selection: r=8–64 typical. Higher rank = more capacity but more parameters. α/r scaling (usually α=2r) controls adapter contribution magnitude.
Q21 How does Retrieval-Augmented Generation (RAG) integrate with Transformers?
+

RAG (Lewis et al., 2020) augments a parametric LLM with non-parametric retrieval. At inference time:

  • Query is embedded and used to retrieve top-k relevant documents from a vector store (dense retrieval via DPR, E5, etc.)
  • Retrieved documents are concatenated into the context window
  • The LLM generates conditioned on both the query and retrieved context

Architecture variants:

  • RAG-Sequence — retrieve once; generate full answer conditioned on same document
  • RAG-Token — re-retrieve at each generation step (expensive but more accurate)
  • FLARE / ITER-RETGEN — iterative retrieval during generation when the model expresses uncertainty

Key challenge: lost-in-the-middle — LLMs tend to attend poorly to information in the middle of long contexts. Mitigated by reranking and positional ordering strategies.

Q22 What causes hallucinations in LLMs and how can they be mitigated?
+

LLM hallucinations — generating confident but incorrect facts — stem from several interacting causes:

  • Knowledge gaps: the pre-training corpus may lack or have noisy coverage of certain facts
  • Distribution shift: RLHF trains for perceived quality, inadvertently rewarding fluency over factuality
  • Sycophancy: models trained on human feedback learn to agree with the user rather than be accurate
  • Overconfident prediction: next-token cross-entropy loss does not penalize confident wrong predictions differently from uncertain ones

Mitigation strategies:

  • RAG — ground generation in retrieved documents
  • Chain-of-thought + self-consistency — sample multiple reasoning paths, take majority vote
  • Calibration fine-tuning — train the model to express uncertainty
  • Constitutional AI / factuality RLHF — reward factual accuracy explicitly
Q23 What is activation checkpointing and how does it trade compute for memory?
+

During backpropagation, PyTorch stores all intermediate activations from the forward pass (needed to compute gradients). For a transformer with L layers and sequence length n, this is O(L·n·d) memory.

Gradient/activation checkpointing stores only a subset of activations (checkpoints) during the forward pass — typically at the boundary of each Transformer block — and recomputes the remaining activations during backpropagation:

  • Memory: O(√L · n · d) instead of O(L · n · d)
  • Compute overhead: ~33% extra FLOPs (one extra forward pass per layer during backward)
  • In practice: reduces activation memory by ~8-12× for GPT-scale models

Used with torch.utils.checkpoint.checkpoint() in PyTorch. Essential for fine-tuning large models (QLoRA training) on limited GPU memory.

Q24 What are the key architectural differences between Transformer-based models and State Space Models (SSMs) like Mamba?
+

SSMs (S4, H3, Mamba) represent an alternative to attention for sequence modeling:

  • Recurrent inference: like RNNs, SSMs run in O(1) per step at inference — no KV cache needed
  • Linear training: can be computed as a convolution over the sequence — O(n log n) with FFT vs O(n²) for attention
  • Selective State Spaces (Mamba): makes SSM parameters input-dependent, giving it selective attention-like ability

Comparison:

  • Transformers: exact recall of all prior tokens, O(n²) compute, excellent for tasks requiring in-context lookup
  • Mamba: O(n) compute and memory, fast inference, but limited long-range recall (compresses context into fixed-size state)
  • Hybrid (Jamba, Zamba): interleave SSM and attention layers to combine strengths
Mamba-2 established a theoretical connection between SSMs and linear attention, unifying both under the "structured state space duality" framework.
